# Context7 MCP 怎样让代码建议有匹配的文档依据

[English](context7-mcp.md) | 简体中文 · [全部指南](../README.zh.md)

这是 [Upstash 官方 Context7 Skill](https://github.com/upstash/context7/tree/master/skills/context7-mcp) 的使用说明。它适用于库、框架、API 和配置问题，帮助助手先取得相关文档，再解释怎样使用。你给出具体版本和具体问题后，更容易取得有用的材料。

例如，同一个库在不同版本中可能有不同接口。只让助手凭记忆写代码，很难知道建议来自哪个版本。Context7 的作用是补上查文档的过程，实际项目仍需要编译或测试。

## 先安装并连接

它属于外部 Skill，不包含在本集合安装的 9 个 Skill 中。可以单独安装。

```sh
npx skills@latest add upstash/context7 --skill context7-mcp
```

选择 Codex 等目标 Agent，并按上游说明配置 Context7 MCP 服务。Skill 和服务连接要分别具备，只有其中一项还不能完成文档查询。本集合的[子模块目录](../../skills/research/context7-mcp)仅记录上游仓库的固定提交，正常情况下不检出内容，也不等于安装完成。

## 怎样问才容易查到有用内容

下面用 Prisma 的分页问题作教学示例，不在本页承诺任何版本的具体 API 写法。

```text
$context7-mcp
先确认当前项目依赖的 Prisma 版本。
查匹配的官方文档，解释游标分页的查询方式和排序要求。
先在对话中给代码示例、版本依据和文档链接，不修改项目文件。
如果找不到匹配版本的资料，明确说明。
```

这是通过 Skills CLI 单独安装到 Codex 后的名称，不使用本集合的 `skills` 插件前缀。通过上游自己的插件安装时，按上游提供的名称调用。

助手会先确认查询对象，选择正确的文档来源，再取得与问题对应的内容。多个互不相关的问题适合分别查询，避免一次请求把结果分散到几件事上。

## 最后得到什么，会不会生成文件

上面的请求应得到对话中的解释、示例代码和文档来源，通常不会生成文件。查询文档本身也不会把项目依赖升级到新版本，或自动安装对应 SDK。

如果你另行要求“按文档把分页加到项目里”，才会进入实际实现阶段。此时修改哪些源文件、测试和配置，由目标项目决定。需要验证的仍然是本项目里的实际行为。

也可以明确要求将查阅结果保存到 `docs/pagination-notes.md`。这个路径来自你的保存要求，Context7 没有固定的笔记输出文件。

## 怎样验收

先看建议是否说明使用的库和版本，再沿链接检查代码建议是否有文档支持。版本不匹配、只有社区同名项目或缺少相关材料时，助手应把限制写清楚。查到一个接口，也不能直接宣称本项目的实现已经通过运行验证。
