# Wait What：重新解释没听懂的回答

[English](wait-what.md) | 简体中文 · [全部指南](../README.zh.md)

`wait-what` 让助手补齐上下文，以更明确的逻辑和一致的术语重新解释上一条回答。适用于没听懂说明的情况，而不是在回答前澄清任务本身。

本集合内置的是 Matt Pocock 原技能的维护改编版。[来源与许可说明](../../skills/thinking/wait-what/NOTICE.md)记录其出处，[MIT 许可证](../../skills/thinking/wait-what/LICENSE)随技能保留。

## 在没听懂的回答后调用

这个技能仅由用户显式调用。使用本集合的 Codex 插件时，可以发送：

```text
$skills:wait-what
我没听懂缓存失效为什么会让下一次请求得到新结果。
请重新解释这个联系，说明前提假设，并给一个具体例子。
```

单独安装时用 `$wait-what`，Claude Code 中用 `/skills:wait-what`。也可以只调用技能，不指定具体疑点，让助手重新解释上一条回答。

## 预期结果

- 从没讲清楚的地方重新解释，明确缺失的前提、问题当前进展和所作假设。
- 使用你当前的语言回答。
- 措辞直接，条件和结果明确，术语一致，并简短定义技术术语。
- 先回答核心问题，再补充理解所需的背景和示例，保留必要细节与风险。
- 区分已核实的事实、推断、假设和建议。

重新解释默认留在对话中，没有固定文件产物。不依赖 `GLOSSARY.md`、项目专用文档或外部服务。

## 怎样检查结果

检查新回答是否解释了缺失的联系，而不是重复原来的措辞。必要的前提、术语、假设和限制应当明确可见。表达更清楚不代表技术判断已获验证，仍需核对相关证据。

具体行为由[技能指令](../../skills/thinking/wait-what/SKILL.md)定义。如果需要在回答前澄清任务本身，使用 [clarify](clarify.zh.md)。
